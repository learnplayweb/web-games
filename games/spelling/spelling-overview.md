# 맞춤법 게임 전체 개요

## 목적

맞춤법 문제를 풀면서 캐릭터가 징검다리를 이동하는 웹게임이다.

문제은행에서 맞춤법 문제를 출제하고, 플레이어가 좌우 방향키로 정답 블록을 선택한다.

모바일과 PC에서 모두 플레이할 수 있어야 한다.

---

## 기본 게임 구조

* 한 스테이지는 약 10문제로 구성한다.
* 문제는 문제은행에서 가져온다.
* 스테이지 내 문제 출제 순서는 랜덤이다.
* 생성형 문제는 사용하지 않는다.
* 문제마다 정답과 오답 선택지가 하나씩 존재한다.
* 정답과 오답의 좌우 위치는 문제마다 랜덤으로 배치한다.
* 좌우 위치가 바뀌면 정답 방향도 함께 변경한다.

---

## 화면 구성

### 상단

시계 게임과 동일한 높이와 배치 기준을 사용한다.

* 왼쪽: Combo
* 오른쪽: 목숨
* 목숨은 채워진 하트 3개로 표시한다.
* 오답마다 하트 하나가 빈 하트로 변경된다.

예:

❤️❤️❤️ → ❤️❤️♡ → ❤️♡♡ → ♡♡♡

### 캐릭터 영역

* 상단에서 약 1/3 지점까지 캐릭터를 표시한다.
* 캐릭터는 정면을 바라본다.
* 게임 진행 중 캐릭터의 기준 위치는 게임 영역 가운데 부근이다.
* 캐릭터가 점프할 때 위로 올라갔다가 내려오는 동작을 한다.
* 점프 시 팔다리도 움직여 실제로 뛰는 듯한 느낌을 표현한다.

### 게임 진행 영역

화면 중앙의 가장 넓은 영역을 사용한다.

기본적으로 다음 세 블록을 표시한다.

[ 이전 블록 ]

```
 캐릭터
[현재 블록]

[다음 블록]
```

모든 블록은 기본적으로 화면 가운데 정렬한다.

### 진행용 키패드

화면 아래 약 1/5 영역에 배치한다.

* 왼쪽: ←
* 가운데: ↓
* 오른쪽: →

시계 게임의 키패드와 동일한 디자인 계열을 사용한다.

* ↓ 버튼: 점프
* ← 버튼: 왼쪽 블록으로 이동
* → 버튼: 오른쪽 블록으로 이동

PC에서는 키보드로도 조작할 수 있다.

* ←: 왼쪽 이동
* →: 오른쪽 이동
* ↓: 점프
* Space: 점프

---

## 블록 구조

캐릭터가 납작한 블록 위에 서서 이동한다.

블록은 징검다리처럼 일정한 간격으로 배치한다.

게임 진행 방향은 **화면 아래에서 위쪽**이다.

캐릭터가 실제 화면을 계속 이동하는 것이 아니라 블록이 화면 아래에서 위로 흘러가면서 진행감을 표현한다.

### 블록 원근감

다음 블록:

* 위에서 넓은 평면을 내려다보는 듯한 각도
* 윗면이 넓게 보인다.
* 문장 성분이 잘 보이도록 한다.

현재 블록:

* 다음 블록보다 약간 작다.
* 시점이 조금 더 정면에 가깝다.
* 납작한 옆면이 조금 더 보인다.

이전 블록:

* 현재 블록보다 약간 작다.
* 더욱 정면에 가까운 시점이다.
* 납작한 옆면이 더 많이 보인다.

블록이 이동할 때 위치와 크기 및 원근감이 자연스럽게 변화한다.

---

## 게임 진행 규칙

일반 블록에서는 중앙에 위치한다.

일반 블록:

중앙 일반 블록
↓ 점프
다음 중앙 블록

맞춤법 문제에서는 갈림길이 생성된다.

중앙 현재 블록
↓
왼쪽 블록 / 오른쪽 블록
↓
좌우 방향키로 선택

* ← 또는 → 입력으로 선택한 블록으로 점프한다.
* 선택한 블록에 착지한다.
* 정답이면 계속 진행한다.
* 오답이면 낙하 연출을 실행한다.
* 선택 블록에서 중앙으로 돌아올 때는 좌우 방향키를 사용하지 않는다.
* **점프 버튼을 눌러 중앙 일반 블록으로 복귀한다.**

따라서 문제 하나는 다음 사이클로 구성한다.

중앙 일반 블록
→ 갈림길
→ 좌우 선택
→ 선택 블록
→ 점프
→ 중앙 복귀

---

## 정답 처리

정답을 선택하면:

* 선택한 블록에 초록색 정답 표시를 한다.
* 시계 게임의 정답 표시 디자인을 참고한다.
* 다음 진행으로 넘어간다.
* 선택 블록에서 중앙 일반 블록으로 복귀한다.
* 다음 문제를 진행한다.

---

## 오답 처리

오답을 선택하면:

* 선택한 블록에 빨간색 표시를 한다.
* 블록과 캐릭터가 아래로 떨어지는 연출을 한다.
* 목숨을 하나 감소시킨다.
* 캐릭터가 다시 나타난다.
* 일정 시간 동안 캐릭터가 깜박인다.
* 캐릭터는 해당 갈림길 직전의 일반 중앙 블록에서 다시 시작한다.
* 현재 문제는 다시 풀 수 있도록 유지한다.

목숨이 모두 소진되면 스테이지를 종료한다.

---

## 문제 데이터

문제 데이터에는 좌우 위치를 고정하지 않는다.

예:

정답: 않았더니
오답: 안았더니

게임 실행 시 랜덤으로 배치한다.

경우 1:

[않았더니] [안았더니]

경우 2:

[안았더니] [않았더니]

문제 데이터와 실제 표시 위치를 분리한다.

---

## 문제 표시 예시

문장은 가운데 정렬한다.

[밥을]

[먹지]

[않았더니] [안았더니]

[배가]

[고프다.]

맞춤법 선택 부분만 좌우로 갈라지고 나머지 문장 성분은 중앙에 배치한다.

---

## 스테이지

* 한 스테이지 약 10문제
* 문제은행에서 출제
* 스테이지 내 출제 순서는 랜덤
* 모든 문제를 완료하면 스테이지 성공
* 목숨이 0이 되면 스테이지 실패

---

## 보상

게임 중 실제 Gold를 즉시 지급하지 않는다.

스테이지가 정상적으로 완료된 후 최종 결과에서 보상을 계산하고 지급한다.

새로고침이나 게임 중 이탈로 동일한 문제를 반복하여 Gold를 획득할 수 없어야 한다.

별점 보상: 소진된 목숨 개수 기준 (0개 소진=3별, 1개=2별, 2개=1별)

* ★ = 10 Gold
* ★★ = 30 Gold
* ★★★ = 50 Gold

최고 별점 갱신 시 보상은:

새 최고 별 가치 − 이전 최고 별 가치

로 계산한다.

콤보 보너스:

최장 콤보 × COMBO_MULTIPLIER

* COMBO_MULTIPLIER 초기값: 4

---

## 구현 방향

* 기존 Web Games 프로젝트 구조와 스타일을 유지한다.
* 시계 게임의 UI 디자인과 공통 요소를 최대한 재사용한다.
* 캐릭터 시스템과 기존 저장 시스템을 활용한다.
* 모바일 우선으로 구현한다.
* PC 키보드 조작을 지원한다.
* 기존 기능을 깨뜨리지 않는다.
* 각 기능은 역할을 분리하여 구현한다.
* 구현 단계별로 필요한 기능만 추가한다.
* 이후 단계의 기능을 미리 구현하지 않는다.
