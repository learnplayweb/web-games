# 맞춤법 게임 전체 개요

## 목적

맞춤법 문제를 풀면서 캐릭터가 징검다리를 이동하는 웹게임이다.
문제은행에서 맞춤법 문제를 출제하고, 플레이어가 좌우 방향키로 정답 블록을 선택한다.
모바일과 PC에서 모두 플레이할 수 있어야 한다.

---

## 기본 게임 구조

* 한 마당(스테이지)은 약 10문제로 구성하고 목숨은 3개 부여한다.
* 문제는 문제은행에서 가져온다.
* 마당 내 문제 출제 순서는 랜덤이다.
* 생성형 문제는 사용하지 않는다.
* 문제마다 정답과 오답 선택지가 하나씩 존재한다.
* 정답과 오답의 좌우 위치는 문제마다 랜덤으로 배치한다.
* 좌우 위치가 바뀌면 정답 방향도 함께 변경한다.
* 다섯 마당마다 복습 마당이 있으며 해당 구간의 문제를 랜덤 출제한다.
* 복습 마당은 20문제로 구성하고 목숨은 5개를 부여한다.

## 마당 구조
기존의 스테이지 명칭을 마당으로 변경한다.

* 일반 마당: 학습과 진행 중심
    * 기본적인 게임 진행 단위
    * 시작할 때, 오답 시 학습 내용 담은 모달 띄움
    * 문제은행에서 문장 단위로 문제를 랜덤 출제
    * 목숨 3개 적용, 조작 실수 시 차감
    * 정답/오답에 따른 게임 진행은 유지

* 복습 마당: 도전 콘텐츠
    * 5개 일반 마당마다 1개씩 배치
    * 이전 마당의 문제를 종합하여 출제
    * 해당 구간의 문제 중 20문장을 랜덤으로 출제
    * 목숨 5개 적용, 오답 및 조작 실수 시 차감

------

## 문제은행 구조
* 문제의 단위는 문장으로 정의한다.
* 각 문장에는 1개 이상의 맞춤법 선택 지점이 포함될 수 있다.
* 문제를 출제할 때는 문장 전체를 하나의 데이터 객체로 선택한다.
* 문장 내부의 맞춤법 선택 지점이 서로 다른 문제로 분리되지 않도록 한다.
* 문제의 단위는 문장으로 정의한다.
* 한 문장에 포함된 맞춤법 선택 지점의 개수는 문제 수와 다를 수 있다.
* 마당 내 출제 순서는 문장 단위로 랜덤화한다.
* 선택지의 좌우 위치는 각 선택 지점마다 랜덤으로 배치한다.
* 좌우 위치가 변경되면 정답 방향도 함께 변경한다.

예:
문제 1 = "밥을 [안/않] 먹었는데도 배가 고프지 [안다./않다.]"

→ 문제 1개로 처리하며, 내부에 맞춤법 선택 지점이 2개 존재함.

## 화면 구성

### 상단

시계 게임과 동일한 높이와 배치 기준을 사용한다.

* 왼쪽: Combo
* 오른쪽: 목숨
* 목숨은 채워진 하트 3개로 표시한다.
* 오답마다 하트 하나가 빈 하트로 변경된다.

예:

❤️❤️❤️ → ❤️❤️♡ → ❤️♡♡ → ♡♡♡

### 캐릭터 영역

* 상단에서 약 1/3 지점까지 캐릭터를 표시한다.
* 캐릭터는 정면을 바라본다.
* 게임 진행 중 캐릭터의 기준 위치는 게임 영역 가운데 부근이다.
* 캐릭터가 점프할 때 위로 올라갔다가 내려오는 동작을 한다.
* 점프 시 팔다리도 움직여 실제로 뛰는 듯한 느낌을 표현한다.

### 게임 진행 영역

화면 중앙의 가장 넓은 영역을 사용한다.

기본적으로 다음 세 블록을 표시한다.

[ 이전 블록 ]

```
 캐릭터
[현재 블록]

[다음 블록]
```

모든 블록은 기본적으로 화면 가운데 정렬한다.

### 진행용 키패드

화면 아래 약 1/5 영역에 배치한다.

* 왼쪽: ←
* 가운데: ↓
* 오른쪽: →

시계 게임의 키패드와 동일한 디자인 계열을 사용한다.

* ↓ 버튼: 점프
* ← 버튼: 왼쪽 블록으로 이동
* → 버튼: 오른쪽 블록으로 이동

PC에서는 키보드로도 조작할 수 있다.

* ←: 왼쪽 이동
* →: 오른쪽 이동
* ↓: 점프
* Space: 점프

## 블록 구조

캐릭터가 납작한 블록 위에 서서 이동한다.

블록은 징검다리처럼 일정한 간격으로 배치한다.

게임 진행 방향은 **화면 아래에서 위쪽**이다.

캐릭터가 실제 화면을 계속 이동하는 것이 아니라 블록이 화면 아래에서 위로 흘러가면서 진행감을 표현한다.

### 블록 원근감

다음 블록(진행 영역 아래쪽에 위치):

* 위에서 넓은 평면을 내려다보는 듯한 각도
* 윗면이 넓게 보인다.
* 문장 성분이 잘 보이도록 한다.

현재 블록:

* 다음 블록보다 약간 작다.
* 시점이 조금 더 정면에 가깝다.
* 납작한 옆면이 조금 더 보인다.

이전 블록(진행 영역 위쪽에 위치):

* 현재 블록보다 약간 작다.
* 더욱 정면에 가까운 시점이다.
* 납작한 옆면이 더 많이 보인다.

블록이 이동할 때 위치와 크기 및 원근감이 자연스럽게 변화한다.

---

## 게임 진행 규칙

일반 블록에서는 중앙에 위치한다.

일반 블록:

중앙 일반 블록
↓ 점프
다음 중앙 블록

맞춤법 문제에서는 갈림길이 생성된다.

중앙 현재 블록
↓
왼쪽 블록 / 오른쪽 블록
↓
좌우 방향키로 선택

* ← 또는 → 입력으로 선택한 블록으로 점프한다.
* 선택한 블록에 착지한다.
* 정답이면 계속 진행한다.
* 오답이면 낙하 연출을 실행한다. (일반 마당에서는 학습 모달 표시)
* 선택 블록에서 중앙으로 돌아올 때도 알맞은 좌우 방향키를 사용한다.
* 일반 블록으로 이동 시 점프(↓)가 아닌 좌우 방향키를 누르면 추락하며 목숨이 소진된다.

문제 사이클 구성 예시:

중앙 일반 블록
→ 갈림길
→ 좌우 선택
→ 선택 블록
→ 좌우 선택
→ 중앙 일반 블록

---

## 정답 처리

정답을 선택하면:

* 선택한 블록에 초록색 정답 표시를 한다.
* 시계 게임의 정답 표시 디자인을 참고한다.
* 다음 진행으로 넘어간다.
* 선택 블록에서 중앙 일반 블록으로 복귀한다.
* 다음 문제를 진행한다.

---

## 오답 처리

오답을 선택하면:

* 선택한 블록에 빨간색 표시를 한다.
* 블록과 캐릭터가 아래로 떨어지는 연출을 한다.
* 목숨을 하나 감소시킨다.
* 캐릭터가 다시 나타난다.
* 일정 시간 동안 캐릭터가 깜박인다.
* 캐릭터는 해당 갈림길 직전의 일반 중앙 블록에서 다시 시작한다.
* 현재 문제는 다시 풀 수 있도록 유지한다.

목숨이 모두 소진되면 마당을 종료한다.

---

## 문제 데이터

문제 데이터에는 좌우 위치를 고정하지 않는다.

예:

정답: 않았더니
오답: 안았더니

게임 실행 시 랜덤으로 배치한다.

경우 1:

[않았더니] [안았더니]

경우 2:

[안았더니] [않았더니]

문제 데이터와 실제 표시 위치를 분리한다.

문장은 가운데 정렬한다.

[밥을]

[먹지]

## 마당

* 한 마당 약 10문제
* 문제은행에서 출제
* 마당 내 출제 순서는 랜덤
* 모든 문제를 완료하면 마당 성공
* 목숨이 0이 되면 마당 실패

---

## 보상

문제당 Gold * 선택 지점마다 맞힌 수로 한다. (문장마다 아님)
게임 중 Gold를 즉시 지급하지 않는다.
마당이 정상적으로 완료된 후 최종 결과에서 보상을 계산하고 지급한다.
목숨 소진으로 마당을 끝내지 못할 경우에도 보상을 획득할 수 없다.
새로고침이나 게임 중 이탈로 동일한 문제를 반복하여 Gold를 획득할 수 없어야 한다.
목숨은 보상과 관계 없다. (마당 완료를 위한 실패 조건으로만 작용)

# 일반 마당 보상

### 문제 정답 보상

단계별 최고 별점에 따라 정답인 문제당 획득 Gold를 차등 적용한다.

| 저장된 최고 별점 | 문제당 Gold |
| -------- | -------: |
| 없음       |      +10 |
| ★        |       +7 |
| ★★       |       +4 |
| ★★★      |       +1 |

---

### 콤보 보너스

단계 종료 시 최장 Combo를 기준으로 보너스를 지급한다.

```
Combo Bonus = maxCombo × COMBO_MULTIPLIER
```

단계별 최고 별점에 따라 COMBO_MULTIPLIER를 차등 적용한다.

| 이전 최고 별점 | COMBO_MULTIPLIER |
| -------- | ---------------: |
| 없음       |                4 |
| ★        |                3 |
| ★★       |                2 |
| ★★★      |                1 |

COMBO_MULTIPLIER는 상수로 관리하며, 밸런스 테스트 결과에 따라 쉽게 조정할 수 있도록 구현한다.


---

### 별점

정답률에 따라 별점을 부여한다.

| 정답률    | 별점  |
| ------ | --- |
| 100%   | ★★★ |
| 2/3 이상 | ★★  |
| 1/3 이상 | ★   |
| 1/3 미만 | 없음  |

---

### 별점 보상

별점의 가치는 다음과 같다.

| 별점  | Gold |
| --- | ---: |
| ★   |   10 |
| ★★  |   30 |
| ★★★ |   50 |

최초 도전 또는 최고 별점 갱신 시 지급 Gold는

```
새 최고 별 가치 − 이전 최고 별 가치
```

로 계산한다.

예)

* 없음 → ★ = +10
* ★ → ★★ = +20
* ★★ → ★★★ = +20
* ★ → ★★★ = +40

별점 유지 또는 하락 시 추가 Gold는 지급하지 않는다.

---

### 최고 별점 저장

최고 별점은 게임 전체가 아니라 **각 게임의 각 마당별로 독립 저장**한다.

예)

* 맞춤법 마당 1 : ★★★
* Clock Lv.2 : ★★
* Number Connect Lv.1 : ★★★

## 구현 방향

* 기존 Web Games 프로젝트 구조와 스타일을 유지한다.
* 시계 게임의 UI 디자인과 공통 요소를 최대한 재사용한다.
* 캐릭터 시스템과 기존 저장 시스템을 활용한다.
* 모바일 우선으로 구현한다.
* PC 키보드 조작을 지원한다.
* 기존 기능을 깨뜨리지 않는다.
* 각 기능은 역할을 분리하여 구현한다.
* 구현 단계별로 필요한 기능만 추가한다.
* 이후 단계의 기능을 미리 구현하지 않는다.
