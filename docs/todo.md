## !! 수정
문제 맞힐 때 골드 바로 상승
> 이때 새로고침하면 쉬운 단계만 계속 풀어 골드 획득 부작용
> 게임 내 골드 표시를 없애고 최종 결과 나왔을 때 골드 반영으로 수정
 - 정답 시 골드는 즉시 증가하지 않음.
 - 게임 내부에서는 획득 예정 골드만 변수로 관리함.
 - 새로고침하면 해당 게임 세션의 획득 예정 골드도 함께 초기화됨.
 - 정상적으로 게임을 완료하면 최종 결과 화면에서 실제 Gold에 한 번만 합산함.
 - 결과 반영 후 저장함.
 
 * 중요: 최종 보상 처리를 반드시 한 번만 실행

## 4단계 — 파티클 효과 실행 시스템
효과를 실제 화면에 표시하는 공통 함수 구현
효과 생성/실행/삭제 관리
특정 이벤트와 연결하지 않고 테스트용 호출만 구현
게임이나 상점 어디서든 호출할 수 있는 구조로 작성

→ 이 단계에서 "효과 자체가 정상적으로 작동하는지" 검증.

## 5단계 — 효과 선택 시스템

이 단계에서 다음 규칙을 만들어 둡니다.

보유 효과 1개
→ 해당 효과 선택

보유 효과 2개 이상
→ 보유 효과 중 랜덤 선택

그리고 특정 효과를 제외해야 하는 경우도 여기서 처리할 수 있습니다.

예:

현재 장착 효과
→ 랜덤 후보에서 제외

## 6단계 — 게임 이벤트 연결

게임의 기존 이벤트에 효과를 연결.
예 콤보 달성
→ playEffect()

특정 콤보
→ playEffect()

→ 효과 시스템과 게임 로직을 분리.

## 7단계 — 이벤트별 효과 규칙 설정

이벤트 자체의 규칙만 정합니다.

예:

정답       → effectType: "correct"
3*n 콤보      → effectType: "combo"


그리고 실제 랜덤 선택은 5단계의 공통 시스템이 담당합니다.

즉,

게임 이벤트
    ↓
"어떤 종류의 효과인가?"
    ↓
효과 선택 시스템
    ↓
보유 효과 중 랜덤 선택
    ↓
파티클 실행
