게임 로직(script.js)이 효과에 대해 아주 멍청해지도록(단순해지도록) 만들어야 합니다.
1. 선택 시스템 분리 (inventory.js 또는 공통 파일에 추가)
getRandomEquippedEffect(excludeId) 같은 전용 함수를 만듭니다.
장착된 배열을 가져와서 1개면 반환, 2개 이상이면 excludeId를 피해서 랜덤 반환하는 로직을 공통화합니다. (전역 변수 오염도 막을 수 있습니다.)
2. 통합 실행 매니저 구축 (script.js 외부 또는 내부 상단)
playEventEffect(eventType, targetElement) 함수를 하나 만듭니다.
내부에서 이벤트 타입(예: 'combo', 'correct')에 따라 조건을 걸고, 위 1번에서 만든 함수로 효과를 뽑아 spawnEffect에 넘겨주는 "라우터(중계기)" 역할을 하게 합니다.
3. 게임 이벤트 다이어트 (script.js 핵심 로직)

## 5단계 — 효과 선택 시스템 > 결합도 높음
현재 상황: 보유 효과 중 랜덤 선택, 전역 변수(window.lastSpawnedEffectId)를 활용한 중복 제외 로직이 시계 게임의 games/clock/script.js 안(checkAnswer 함수 내부)에 날것 그대로 노출되어 있습니다.
문제점: 다른 게임(예: number-connect)을 추가할 때 이 복잡한 랜덤 선택 로직을 또 복사해서 붙여넣어야 합니다.

이 단계에서 다음 규칙을 만들어 둡니다.

보유 효과 1개
→ 해당 효과 선택

보유 효과 2개 이상
→ 보유 효과 중 랜덤 선택

그리고 특정 효과를 제외해야 하는 경우도 여기서 처리할 수 있습니다.

예:

현재 장착 효과
→ 랜덤 후보에서 제외

## 6단계 — 게임 이벤트 연결 > 추상화 부족
현재 상황: 3의 배수 콤보를 확인하는 if문 안에, 효과를 고르고 실행하는 모든 과정이 섞여 있습니다.
문제점: 향후 "정답 시 효과", "클리어 시 효과" 등을 추가하려면 script.js가 무한정 길어지고 지저분해집니다.

게임의 기존 이벤트에 효과를 연결.
예 콤보 달성
→ playEffect()

특정 콤보
→ playEffect()

→ 효과 시스템과 게임 로직을 분리.

## 7단계 — 이벤트별 효과 규칙 설정

이벤트 자체의 규칙만 정합니다.

예:

정답       → effectType: "correct"
3*n 콤보      → effectType: "combo"


그리고 실제 랜덤 선택은 5단계의 공통 시스템이 담당합니다.

즉,

게임 이벤트
    ↓
"어떤 종류의 효과인가?"
    ↓
효과 선택 시스템
    ↓
보유 효과 중 랜덤 선택
    ↓
파티클 실행
