## 맞춤법 게임 개발 로드맵
- 메인화면의 맞춤법 게임 카드는 캐릭터 등록해야 활성화

### 1단계. 게임 기본 화면 구현

**목표:** 시계 게임과 통일된 기본 UI 구성

* 모바일 우선 레이아웃
* PC에서도 가운데 정렬
* 최상단 정보 영역
  * 왼쪽: `Combo`
  * 오른쪽: `❤️❤️❤️`
  * 높이와 글자 위치는 시계 게임과 동일한 기준 사용
* 최상단 아래~키패드 위: 게임영역 약 1/3 영역
  * 캐릭터가 정면을 바라보도록 표시
* 화면 아래 약 1/5
  * 진행용 키패드 배치
  * 왼쪽: `←`
  * 가운데: `↓` (굵고 크게)
  * 오른쪽: `→`
  * 버튼은 시계 게임 키패드와 동일한 디자인 계열
  * 가운데 `↓` 버튼은 점프
* 나머지 가운데 영역
  * 게임 진행 영역
  * 가운데에 캐릭터 위치

---

### 2-1단계. 블록 배치 구현

**목표:** 캐릭터와 징검다리 블록의 기본 이동 구현

블록 배치
* 블록은 징검다리 형태로 배치
* 기본 블록은 화면 중앙 정렬
* 게임 진행 방향은 화면 아래 → 위
* 화면에는 기본적으로
    이전 블록
    현재 블록
    다음 블록
을 표시

블록 원근 표현

* 이동할 블록(다음 블록)
    위에서 넓은 평면을 내려다보는 듯한 각도
    블록의 윗면이 넓게 보이도록 표시
    문장 성분이 잘 보이도록 구성

* 현재 블록
    다음 블록보다 약간 작게 표시
    시점이 정면에 가까워짐
    윗면은 좁아지고 납작한 옆면이 조금 더 보이도록 표현

* 이전 블록
    현재 블록보다 약간 작게 표시
    더 정면에 가까운 시점
    납작한 옆면이 더 많이 보이도록 표현

즉:
       [ 이전 블록 ]
        ────────
       /________/
        

          캐릭터
       [ 현재 블록 ]
         ─────────
        /        /
       /________/



       [ 다음 블록 ]
        ───────────
       /           /
      /           /
     /───────────/

실제 디자인은 자연스러운 원근감이 느껴지도록 조정.

### 3-1단계. 점프 및 키보드 조작 구현

**목표:** 모바일과 PC에서 동일한 게임 조작 제공

#### 모바일

* `↓` 버튼 → 점프
* `←` 버튼 → 왼쪽으로 점프
* `→` 버튼 → 오른쪽으로 점프

#### PC 키보드

* `↓` → 점프
* `Space` → 점프
* `←` → 왼쪽 선택
* `→` → 오른쪽 선택

#### 이동 규칙

일반 블록:

중앙
 ↓ 점프
중앙
```

맞춤법 갈림길:

```text
          현재
           ↓

     [왼쪽]   [오른쪽]
        ←       →
```

* `←` 또는 `→` 입력으로 해당 블록을 선택하며 점프
* 선택한 블록에 착지
* 오입력 시 추락 연출, 목숨 차감


문제 사이클 구성 예시:

중앙 일반 블록
→ 갈림길
→ 좌우 선택
→ 선택 블록
→ 좌우 선택
→ 중앙 일반 블록

#### 캐릭터 점프
* 캐릭터는 게임 진행 영역의 중앙에서 약간 위까지 점프
* 점프 후 다시 현재 블록으로 내려옴
* 실제 수평 이동은 최소화하고 점프 동작을 중심으로 표현
* 점프 중 팔다리가 움직여 실제로 뛰는 듯한 느낌을 표현
* 맞춤법 갈림길에서는 선택한 방향에 맞춰 좌우로 이동하는 점프 연출 적용
* 점프 착지 시 캐릭터와 블록의 위치 관계가 자연스럽게 유지되도록 구현

#### 갈림길 블록 중심 좌표 (board-area 가로 중심 기준)

.fork-row의 두 블록(block--front, 150px)이 gap: 0.9rem(14.4px)로 배치되어 있으므로:

왼쪽 블록 중심: 중심선에서 -82.2px
오른쪽 블록 중심: 중심선에서 +82.2px

계산: 블록폭/2 + gap/2 = 75 + 7.2 = 82.2px
이 값을 캐릭터의 좌/우 착지 좌표로 사용하겠습니다. (반올림하여 ±82px 적용)

### 3-2단계. 블록 진행 구조 및 기본 이동 연출 구현

목표: 캐릭터는 제자리에서 점프(기준 위치 유지)하고, 블록이 아래에서 위로 이동하면서 게임이 진행되는 구조 구현

블록 스크롤
* 캐릭터는 게임 진행 영역 중앙 부근을 유지
* 블록이 화면 아래에서 위로 흘러가는 방식으로 이동
* 블록이 위쪽으로 이동하여 화면 밖으로 사라짐
* 다음 블록이 현재 블록 위치로 이동
* 새로운 다음 블록이 화면 아래쪽에서 생성
* 플레이어의 이동보다는 블록의 이동으로 진행감을 표현
* 블록의 위치와 크기 및 원근 표현은 이동 위치에 따라 자연스럽게 변경


기본 진행 구조

블록이 위로 이동
       ↓
[ 다음 블록 ]
       ↓
캐릭터 점프
       ↓
[ 현재 블록 ]
       ↓
이전 블록이 위로 이동
       ↓
새로운 다음 블록 등장

### 4단계. 문제은행 데이터 구축

**목표:** 게임에서 사용할 맞춤법 문제를 데이터로 분리

* 문제은행 방식 사용
* 생성형 문제는 사용하지 않음
* 한 스테이지에서 출제되는 문제 순서는 랜덤
* 한 스테이지 약 **10문제**
* 문제 데이터에는 좌우 위치를 고정하지 않음

예:

```text
정답: 않았더니
오답: 안았더니
```

게임 실행 시:

```text
정답 → 왼쪽
오답 → 오른쪽
```

또는

```text
오답 → 왼쪽
정답 → 오른쪽
```

으로 랜덤 배치

* 좌우가 바뀌면 정답 방향도 함께 변경
* 따라서 `left`, `right`, `answer`를 문제 데이터에 고정 저장하지 않음

---

### 5단계. 문장 블록 시스템 구현

**목표:** 문제를 실제 게임 블록으로 표시

예시:

```text
[밥을]

[먹지]

[않았더니] [안았더니]

[배가]

[고프다.]
```

* 문장은 가운데 정렬
* 일반 문장 성분은 중앙 블록
* 맞춤법 문제 부분만 좌우 두 블록으로 분기
* 각 블록에 해당 문장 성분 표시
* 게임 진행에 따라 이전/현재/다음 블록을 갱신

---

### 6단계. 정답 판정 및 진행

**목표:** 선택한 블록이 정답인지 판정

정답:

* 선택한 블록에 초록색 표시
* 시계 게임의 정답 표시 디자인을 참고
* 정상적으로 다음 블록 진행
* 갈림길 선택 후 중앙 일반 블록으로 복귀
* 다음 문제 진행

오답:

* 선택한 블록에 빨간색 표시
* 블록과 캐릭터가 아래로 떨어지는 연출
* 하트 1개 감소
* 캐릭터 재등장
* 일정 시간 동안 캐릭터가 깜박임
* 캐릭터는 **해당 갈림길 직전의 일반 중앙 블록**에서 다시 시작
* 현재 문제는 다시 선택할 수 있도록 유지

---

### 7단계. 목숨 시스템

**목표:** 스테이지 실패 조건 구현

초기:

```text
❤️❤️❤️
```

오답 1회:

```text
❤️❤️♡
```

오답 2회:

```text
❤️♡♡
```

오답 3회:

```text
♡♡♡
```

* 목숨은 총 3개
* 오답마다 1개 감소
* 감소한 하트는 채워진 하트 → 빈 하트로 변경
* 목숨이 0이 되면 해당 스테이지 종료
* 이후 결과 화면으로 연결

---

### 8단계. 콤보 시스템

**목표:** 연속 정답을 관리

* 정답 → Combo +1
* 오답 → Combo 0
* 화면 상단 왼쪽에 현재 Combo 표시
* 초기값 `0`
* 기존 시계 게임의 콤보 표시 방식과 통일

※ 현재 단계에서는 **콤보 보너스 보상 계산은 별도 단계로 분리**하는 것이 좋음.

---

### 9단계. 스테이지 진행 및 종료

**목표:** 10문제 단위의 스테이지 완성

* 스테이지 시작
* 문제 10개를 랜덤 순서로 선택
* 문제를 하나씩 진행
* 정답/오답에 따라 이동 및 목숨 처리
* 10문제 완료 → 스테이지 성공
* 목숨 0 → 스테이지 실패
* 정상 종료 시 결과 화면으로 이동

---

### 10단계. 결과 및 보상 시스템

기존에 정리한 보상 시스템과 연결.

* 스테이지 결과에서 최종 결과 계산
* 최고 별점에 따른 별점 보상
* 콤보 보너스
* 실제 Gold 지급은 **게임 중 즉시 지급하지 않고 최종 결과에서 처리**
* 새로고침으로 같은 문제를 반복해서 Gold를 획득하는 문제 방지
* 결과 처리 후 저장

별점 보상:

* ★ = 10 Gold
* ★★ = 30 Gold
* ★★★ = 50 Gold

최고 별점 갱신 시:

`새 최고 별 가치 − 이전 최고 별 가치`

만큼 지급.

콤보 보너스:

`최장 콤보 × COMBO_MULTIPLIER`

* `COMBO_MULTIPLIER = 4`
* 상수로 관리

---

### 11단계. 저장 시스템 연동

* 기존 `SaveManager` 사용
* 문제 진행 중 임시 데이터와 실제 보상 데이터 분리
* 정상적으로 스테이지를 완료한 경우에만 최종 보상 저장
* 새로고침/이탈 시 미완료 게임의 보상은 지급하지 않음
* 기존 저장 구조를 최대한 유지

---

### 전체 진행 흐름

```text
게임 시작
  ↓
문제 10개 랜덤 구성
  ↓
중앙 일반 블록
  ↓
맞춤법 갈림길
  ↓
← / → 선택
  ↓
정답 ─────────→ 초록 표시
  │                 ↓
  │              중앙 복귀
  │                 ↓
  │              다음 문제
  │
  └ 오답 → 빨강 표시
             ↓
          낙하 연출
             ↓
          ❤️ -1
             ↓
      갈림길 직전 중앙 복귀
             ↓
          문제 재도전
             ↓
       ❤️ 0 → 스테이지 실패

10문제 완료
     ↓
스테이지 성공
     ↓
최종 별점/콤보 계산
     ↓
최종 Gold 지급
     ↓
결과 화면
```

**구현 순서상 핵심은 1~6단계를 먼저 완성한 뒤 목숨·콤보·보상·저장을 붙이는 것**입니다. 이렇게 하면 게임의 핵심인 **「블록 이동 → 갈림길 선택 → 정답 판정 → 중앙 복귀」**를 먼저 안정적으로 검증할 수 있습니다.
